# Техническое задание

## Система управления магазином техники + интернет-магазин + склад

**Рабочее название:** `TechStore System`

### 1. Цель системы

Создать единую облачную систему, которая объединяет:

1. Интернет-магазин для клиентов.
2. Управление товарами.
3. Управление складом.
4. Управление заказами.
5. Учёт движения каждого товара.
6. Учёт документов.
7. Клиентов и поставщиков.
8. Доставку и оплату.
9. Возвраты и гарантию.
10. Работу сотрудников с компьютера и телефона.
11. Отчёты и аналитику.

Главный принцип:

> **Любое движение товара должно фиксироваться в системе: кто, что, когда, откуда, куда, по какому заказу/документу.**

# 5. Склад

Система должна поддерживать **несколько складов**.

Например:

```text

    ↓
Магазин
    ↓
Склад №2
    ↓
Товар у курьера
```

Для каждого склада:

* общее количество товаров;
* доступное количество;
* зарезервированное количество;
* ожидаемое поступление;
* товары в пути.

# 6. Приём товара

Когда приходит поставка:

**Поставщик → Приёмка → Проверка → Склад**

Сотрудник открывает:

**"Новая приёмка"**

Выбирает поставщика.

Добавляет:

* товар;
* количество;
* цену закупки;
* серийные номера;
* номер документа поставщика;
* дату;
* склад.

При необходимости фотографирует документ телефоном.

После подтверждения:

> Остаток автоматически увеличивается.

Одновременно создаётся запись в истории:

> 26.09.2026 — товар получен
> Поставщик: ABC Electronics
> Документ: INV-1254
> Количество: 20
> Склад: Main Warehouse
> Сотрудник: Иван

# 7. Перемещение товара

Например:

**Главный склад → Магазин**

Создаётся документ:

**Перемещение №TR-00125**

В нём:

* откуда;
* куда;
* дата;
* сотрудник;
* товары;
* количество;
* серийные номера.

Статусы:

`Создано → Собирается → Отправлено → Получено`

Пока другой склад не подтвердил получение, товар может находиться в состоянии:

**"В пути"**.

Это позволит всегда понимать, где физически находится товар.

# 8. Продажа

Когда клиент оформляет заказ:

```text
Товар на складе
       ↓
Создан заказ
       ↓
Товар резервируется
       ↓
Сотрудник собирает заказ
       ↓
Товар списывается
       ↓
Передан клиенту/курьеру
```

Важно разделить:

**Остаток:** 10
**Зарезервировано:** 2
**Доступно:** 8

Чтобы два клиента одновременно не купили один и тот же товар.

# 27. Важное правило базы данных

Не стоит просто хранить:

> `product.stock = 15`

и каждый раз менять число.

Лучше одновременно вести **журнал операций**:

```text
+20 Получение
-2 Продажа
-3 Перемещение
+1 Возврат
```

Так можно восстановить, **почему остаток стал именно таким**.

## Что получится в итоге

У вас будет одна система:

**Клиент**

`Сайт → Заказ → Оплата → Доставка`

**Менеджер**

`Заказ → Резерв → Сборка → Документ → Отправка`

**Склад**

`Получение → Сканирование → Хранение → Перемещение → Выдача`

**Администратор**

`Продажи + склад + документы + сотрудники + отчёты`

И всё это связано между собой.

Например, клиент заказал **кофемашину**. Менеджер подтвердил заказ → система зарезервировала конкретную единицу → складской сотрудник получил задание на телефоне → отсканировал серийный номер → товар списался со склада → создалась накладная → заказ передан курьеру → клиент получил товар. **Вся цепочка остаётся в истории.**

# 39. Главное правило интерфейса

Я бы заложил принцип:

> **Одна операция — один понятный экран.**

Например, сотрудник склада не должен открывать 5 окон, чтобы принять товар.

Он нажимает:

**📥 Приёмка → 📷 Сканировать → количество → Подтвердить**

Готово.

А менеджер не должен вручную менять остаток после продажи — **заказ и склад должны быть связаны автоматически**.
